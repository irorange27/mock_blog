我自己做饭，偶尔犯懒，厨房垃圾就没及时倒掉。前阵子水果买多了，放在外面，没收进冰箱。过了几天，发现果蝇多了很多，很心烦。这才想到，腐败这种极具生命感的现象从来没有离开过我身边。蔬菜放在外面会出臭水，浴室排水处也会有蛾蚋幼虫，冰箱里放久了的金针菇还会发霉。许多生命活动发生在看不见的地方，却能从气味、幼虫和霉斑里觉察到。

冰箱真是个伟大的发明。它让食物能多放些日子，也让人不必时时惦记着剩菜什么时候会坏。冷藏没有让腐败消失，只是把它放慢了。随着冰箱走进越来越多中国家庭，食物存放渐渐不必费太多心思。这是前辈的智慧和努力带来的生活变化。用得久了，我们甚至忘了冰箱曾经替人解决过多大的麻烦。

过去十五年的科技又给生活带来了多少益处？冰箱的好处在厨房里看得见，移动互联网带来的便利散落在每天的安排里：想买东西时下单，饿了叫外卖，出门前约车；直播和短视频让人有了新的生意、新的表达，也占去了许多时间。点餐、付款、找车这些事背后，许多服务借助数据库保存和读取订单、地址及付款状态，再把前后步骤接起来。它们让日常事务更方便，也让生活多了对网络服务的依赖。AI 也进入了我的写作；我与模型的协作由一轮轮请求和回应构成。

在 Codex 这类 harness 里，用户发来 prompt 后，harness 会把它和系统提示、对话历史、工具定义等上下文组装成请求，送到 server。server 端的 LLM 开始推理，生成文本，或者返回 tool call；harness 接过 tool call，执行工具，把结果写回对话，再发出下一轮请求。多轮对话听起来像一段连续交谈，底下却是一轮轮推理、工具调用和上下文交接。[OpenAI 对 Codex agent loop 的说明](https://openai.com/index/unrolling-the-codex-agent-loop/)

在 Codex 这类把会话历史并入新请求的实现中，每一轮通常会把此前保留的会话历史放进请求。如果新请求保留了完全相同的前缀，又满足缓存条件，server 可以命中 prompt cache，复用前缀对应的 KV 状态，跳过这部分重复计算，也更快开始生成。[OpenAI Prompt Caching 文档](https://developers.openai.com/api/docs/guides/prompt-caching) Cache hit 只减少每轮请求的重复处理，不会让 LLM 在两轮之间继续推理。harness 可以留在运行中，记住对话、等待工具结果或下一次触发；没有新的推理请求时，LLM 本身并不推理。

要我说，AGI 已经来了。只是它仍很昂贵，不是所有人都负担得起大量调用。

梁文锋谈 DeepSeek 的技术路线时，用一段阶梯来描述 AI 的发展：语言模型、CoT、Agent、持续学习、自我迭代，之后才是具身智能。持续学习是下一道关；模型能持续学习后，可以研究并开发自己的下一版，前一阶段形成的能力也能帮助推进后一阶段。先走到自我迭代，再做具身智能，这条路线会轻松得多。[AGI 技术路线实录](https://github.com/KnightQuals/deepseek-investor-meeting/blob/main/DeepSeek%E6%A2%81%E6%96%87%E9%94%8B%E5%9B%9B%E5%B0%8F%E6%97%B6%E6%8A%95%E8%B5%84%E8%80%85%E4%BA%A4%E6%B5%81%E4%BC%9A-02-AGI%E6%8A%80%E6%9C%AF%E8%B7%AF%E7%BA%BF.md)

这条路线也会改变研究者的日常：模型既是研究对象和工具，也可能参与后续模型的研发。

系统要持续运行，不必延长单次推理。传感器、定时器或环境事件带来新信息后，harness 再组装上下文、向 server 发出请求；模型返回结果后，harness 调用工具，或让机器身体采取行动。行动改变环境，新的观察进入下一轮。模型每次仍在单独的请求中推理，系统则靠持续运行的 harness、供电和不断到来的外界信息维持循环。

我还是得把水果收进冰箱。能持续感知和行动的系统有了身体后，便可能在人没有即时发出 prompt 时继续接收环境信息，并改变自己所处的世界。这样的循环如果持续下去，我们会把它看作另一种生命吗？当人类开始创造智能，甚至创造新的生命，自己的位置又在哪里？
